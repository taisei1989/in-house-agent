# macOS UI 設計

## 前提

個人がローカルのエージェントに仕事を依頼し、実行内容を把握して承認する。モデルの準備やサーバー管理をターミナルに戻らず行える構成にする。以下は実装・検証の指針であり、動作確認済みを意味しない。専用の `ux-ia-designer` スキルは利用可能なカタログと標準配置に存在しなかったため、OOUIとApple HIGを基準に設計した。

## オブジェクトモデル

| オブジェクト | 属性 | 操作・関係 |
|---|---|---|
| チャット | タイトル、メッセージ、作業フォルダ | 新規、送信、中止。実行を持つ |
| 実行 | 状態、開始日時、出力、ツール履歴 | 中止、結果表示。チャットまたはルーティンに属する |
| 承認要求 | 操作名、対象パス、引数、書き込み内容 | この操作を許可、拒否。実行に属する |
| ルーティン | 名前、プロンプト、時刻、作業フォルダ、有効状態 | 追加、編集、登録、解除、今すぐ実行。実行履歴を持つ |
| サーバー | 状態、モデル、メモリ、稼働時間、ログ | 起動、停止、再起動 |

## 情報設計

`NavigationSplitView` のサイドバーは「チャット」「ルーティン」「サーバー」の3項目。SF Symbolsはそれぞれ `bubble.left.and.bubble.right`、`calendar`、`server.rack`。選択状態と詳細タイトルを一致させる。サイドバーは標準操作で開閉でき、状態表示は下端に埋め込まずツールバーに置く。[HIG: Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)

### チャット

会話本文、実行状況、下端の複数行入力欄を配置。送信は ⌘↩、新規は ⌘N。生成中は「応答を停止」を表示。ツールの開始・終了・失敗を本文と区別してインライン表示し、引数とログは開閉式にする。未準備なら送信できない理由と「セットアップを開く」または「サーバーを起動」を表示する。既存出力は失敗時も保持する。

ストリーミング中、最下部を読んでいる場合のみ追従する。過去の会話へスクロールしたら追従を止め、「最新の応答へ」を表示する。VoiceOverでトークンごとの読み上げを発生させず、完了と承認待ちの変化を伝える。

### 承認

親ウィンドウに紐づく単一sheetで「何を・どこに・どう変更するか」を表示する。ファイル書き込みは内容または差分、コマンドは引数と作業フォルダを省略せず確認可能にする。「この操作を許可」「拒否」を使用し、包括許可を提供しない。閉じる・Esc・接続断は許可扱いにしない。削除など破壊的操作には destructive role を使い、Returnで誤承認しない。短い不可逆操作の確認のみalertとする。[HIG: Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets)、[Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts)

### ルーティン

一覧に名前、スケジュール、有効状態、直近結果を表示。選択した定義を編集し、保存前にプロンプトと作業フォルダを検証する。日付・時刻は標準コントロールを使い、タイムゾーンを明示する。初期状態では「ルーティンを追加」。登録失敗は一覧を有効表示にせず、原因と再試行を示す。通知拒否時にもアプリ内実行履歴へ到達できるようにする。

無人実行における承認待ちは成功としない。承認を必要とする操作は保留または拒否として記録し、アプリから結果を確認できるようにする。自動承認を暗黙に導入しない。

### サーバー

ツールバーに常時「停止中／起動中／モデル読み込み中／準備完了／エラー」をアイコンとテキストで表示し、起動・停止・再起動は状態に応じて有効化する。詳細画面はモデル名、メモリ、状態、ログを表示。ログは選択・コピー可能とし、ファイルをFinderで表示できるようにする。

起動・読み込みの段階名、経過時間、最新ログを表示する。実測進捗が取得できないSDK処理に架空の百分率を付けない。連続失敗で再起動を打ち切ったら、原因と手動再試行を表示する。[HIG: Progress indicators](https://developer.apple.com/design/human-interface-guidelines/progress-indicators)

### 初回セットアップと設定

長時間のセットアップは専用ウィンドウまたは詳細画面で行う。流れは「保存先と必要条件の確認 → Python環境 → 依存関係 → モデル取得 → 読み込み確認」。実行中の段階、実測可能な取得量、失敗箇所、再試行を示す。「後で設定」で退出可能にする。モデルの既存ファイル選択も用意する。仮想環境やpipの詳細は進捗ログ内に配置する。

`Settings` シーンを ⌘, で開く。一般（サーバー自動起動・更新自動確認）、モデル（モデルパス・作業フォルダ）、クラウド（併用のON/OFF）に分ける。クラウドは明示的なONを要求し、実装されていない場合は有効化できるように見せない。外観はシステムに従う。[HIG: Settings](https://developer.apple.com/design/human-interface-guidelines/settings)

## 共通のUX判断

標準のList・Form・Toolbar・Menu・TextEditorを優先し、システムカラーとフォントを使う。ライト／ダーク、アクセントカラー、Reduce Motionを尊重する。状態を色だけで区別せず、全ボタンにラベルとhelpを付ける。ウィンドウ幅縮小、日本語の長い文言、キーボードのフォーカス移動を確認する。[HIG: Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)

MenuBarExtraは補助入口として状態、アプリを開く、サーバー操作を提供する。独立の管理画面を増やすより、主要画面と同じ操作・状態を共有して不一致を避ける。チャットを中心にしつつ、サーバーの詳細を専用画面へ分離することで日常操作の情報量を抑える。

## フェーズ別の確認・報告

| フェーズ | UIで確認すること | 対応HIG項目 |
|---|---|---|
| 1 雛形 | サイドバー遷移、リサイズ、⌘,、ライト／ダーク | Sidebars・Settings・Accessibility |
| 2 サイドカー | Python単体。UIの達成報告対象外 | 該当なし |
| 3 管理 | 5状態、手動操作、再起動打ち切り、ログ | Progress indicators・Alerts |
| 4 連携 | ストリーミング、中止、スクロール維持 | Progress indicators・Accessibility |
| 5 承認 | 内容確認、許可・拒否・Esc、破壊的操作 | Sheets・Alerts |
| 6 ルーティン | 追加・編集・登録失敗・結果・通知拒否 | Sheets・Settings（タスク内設定） |
| 7 設置 | 初回セットアップ、Dockアイコン、標準ウィンドウ動作 | Settings・Accessibility |
| 8 更新 | 更新メニュー、自動確認設定、安全停止中の状態 | Settings・Progress indicators |

報告では、採用したコンポーネントと実際に検証した操作を分ける。標準部品を使ったことだけでVoiceOverやキーボード操作が検証済みとはしない。最初の実機ウォークスルーは「初回準備 → 質問 → 書き込み拒否 → 許可 → ログ → 定期実行 → 更新」の順とする。
